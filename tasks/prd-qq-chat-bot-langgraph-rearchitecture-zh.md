# PRD：QQ Chat Bot LangGraph 新架构改造

## 当前实现状态

这份 PRD 是 LangGraph 迁移的架构计划，不代表所有目标都已经完成。当前仓库已经具备 MVP graph 包结构（`adapters/`、`graphs/`、`state/`、`nodes/`、`tools/`、`memory_graph/`），普通文本消息会先进入 MVP message graph，再在需要时回退到旧路径。

已经实现或部分实现：
- 类型化 graph state 和 graph output 模型。
- OneBot event 到 graph 输入的标准化适配。
- MVP 消息图：输入标准化、上下文加载、回复决策、回复生成和输出整理。
- 直接回复、不回复、澄清追问、需要工具四类回复策略。
- graph diagnostics，以及不依赖真实 QQ bot 的图测试。
- 工具注册表、工具路由节点、工具执行节点和提醒工具 graph adapter。
- 保守/no-op 的主动行为图骨架。

仍在迁移中：
- 日历、网页搜索、流程工具、部分记忆管理命令和成熟主动行为仍依赖旧 handler 路径。
- `MessageHandler` 仍作为工具型请求的兼容路径存在，直到对应 graph 能力稳定。
- 旧线性编排应按能力逐步退役，不应一次性删除。

## 1. 引言 / 概述

当前 QQ Chat Bot 采用较简易的线性架构。随着长期记忆、主动聊天、提醒、日历、网页搜索、工具调用、人格策略等能力逐渐增加，现有结构已经难以继续清晰扩展。新增功能时，往往需要同时修改消息处理器、LLM 调用、上下文拼接、记忆逻辑和工具逻辑，导致代码耦合高、行为难预测、测试困难、回归风险高。

本次改造的目标是将 bot 核心推翻重建为基于 LangGraph 的智能体架构。nonebot 继续作为 QQ 消息入口和事件适配层，真正的智能行为迁移到 LangGraph 图中执行。系统通过显式状态模型、节点、边、条件路由和可测试执行链路，让 bot 能够根据场景在陪伴、主动行为和工具助理之间切换。

这不是对旧架构的小修小补，而是一次完整的新架构重建。旧架构可以作为迁移参考，也可以在过渡期被包装复用，但长期目标是让核心智能逻辑不再依赖旧的线性处理流程。

## 2. 目标

- 建立以 LangGraph 为核心的 bot 智能体执行框架。
- 将 QQ 事件接入层与智能体决策层解耦。
- 定义统一的图状态模型，用于承载用户消息、会话上下文、记忆检索结果、工具意图、回复策略、工具执行结果和调试信息。
- 支持分阶段迁移旧功能，允许旧能力逐步替换，但最终核心逻辑不依赖旧线性 handler。
- 降低新增工具、新节点、新行为策略的成本。
- 让关键智能行为可以通过单元测试和集成测试验证。
- 形成 MVP / Phase 2 / Phase 3 的长期蓝图，后续可转换为 Ralph 可执行任务。

## 3. 用户故事

### US-001：定义 LangGraph 架构边界

**描述：** 作为开发者，我希望明确 nonebot 事件处理层与 LangGraph 智能体执行层的边界，从而让后续功能都添加到图架构中，而不是继续散落在 handler 中。

**验收标准：**
- [ ] 明确记录 nonebot 只负责 QQ 事件适配。
- [ ] 明确记录 LangGraph 负责消息分析、记忆使用、工具路由、回复决策和回复生成。
- [ ] 定义事件适配器、图构建器、图状态、节点、工具和持久化适配器的模块边界。
- [ ] 标注哪些旧模块只是迁移参考，而不是长期架构约束。
- [ ] 类型检查通过。

### US-002：创建核心图状态模型

**描述：** 作为开发者，我希望有一个类型明确的图状态模型，让每个 LangGraph 节点都能读写可预测的字段。

**验收标准：**
- [ ] 定义状态字段：输入事件元信息、标准化用户消息、会话上下文、记忆结果、意图分类、工具计划、回复策略、生成回复和诊断信息。
- [ ] 状态模型同时支持普通 QQ 消息处理和未来的主动行为任务。
- [ ] 状态模型不在适配层之外直接依赖 nonebot 原始事件对象。
- [ ] 测试覆盖从标准化消息初始化状态的流程。
- [ ] 类型检查通过。
- [ ] 测试通过。

### US-003：构建 MVP 消息图骨架

**描述：** 作为 bot 维护者，我希望有一个最小可用的 LangGraph 消息图，让 QQ 消息能够经过结构化节点后再产生回复。

**验收标准：**
- [ ] 实现 MVP 消息图的 graph builder。
- [ ] MVP 图包含输入标准化、上下文加载、意图 / 回复决策、回复生成和输出整理节点。
- [ ] 图可以在不启动 nonebot 的 Python 测试中被调用。
- [ ] 图返回结构化结果，包括是否回复，以及需要回复时的最终文本。
- [ ] 类型检查通过。
- [ ] 测试通过。

### US-004：将 nonebot 入口接入 LangGraph MVP

**描述：** 作为 QQ 用户，我希望消息由新的 LangGraph 流程处理，让未来 bot 行为来自新的智能体架构。

**验收标准：**
- [ ] nonebot 消息 handler 将原始 QQ 事件转换为标准化图输入。
- [ ] handler 调用 LangGraph MVP 消息图。
- [ ] 只有当图输出表示需要回复时，handler 才发送 QQ 回复。
- [ ] 基础直接聊天场景的关键行为得到保留。

## 4. 功能需求

- FR-1：系统必须使用 LangGraph 作为 bot 智能行为的主要编排层。
- FR-2：nonebot 层必须只负责将 QQ 事件转换为标准化图输入，并执行最终图输出。
- FR-3：图状态必须有明确类型，并且独立于原始 nonebot 事件类。
- FR-4：MVP 消息图必须至少支持输入标准化、上下文加载、回复决策、回复生成和输出整理。
- FR-5：迁移期间可以临时包装旧函数，但图契约不能依赖旧模块内部细节。
- FR-6：回复决策节点必须明确判断不回复、普通回复、澄清追问或工具路由。
- FR-7：记忆节点必须输出结构化记忆，而不是只输出一段不可检查的 prompt 文本。
- FR-8：工具路由节点必须先输出结构化工具计划，再进入工具执行。
- FR-9：工具选择必须与工具执行分离。
- FR-10：回复生成必须消费图状态，并产出最终回复候选。
- FR-11：主动行为必须使用独立图入口，不能混在普通消息处理流程中。
- FR-12：每次图运行必须暴露可用于调试和测试的诊断信息。
- FR-13：测试必须能在不启动真实 QQ bot 的情况下调用图代码。
- FR-14：迁移必须分阶段进行，每个阶段结束后 bot 都应保持可运行。

## 5. 非目标 / 不做范围

- 第一版不迁移 away from nonebot，nonebot 继续作为 QQ 适配层。
- 第一版不开发网页管理后台或图可视化编辑器。
- 架构 MVP 不以接入新的 LLM 供应商为目标。
- 不把项目扩展成通用多人 SaaS bot 平台。
- MVP 不要求迁移所有旧功能。
- 在基础图架构稳定前，不追求完美主动行为。

## 6. 设计考虑

- Bot 应表现为“陪伴型伙伴 + 工具型助手”的混合体。
- 闲聊场景中，bot 应优先考虑连续性、情绪合适度和不过度回复。
- 任务型请求中，bot 应优先考虑意图识别、工具选择、必要确认和可靠执行。
- 主动行为场景中，bot 默认应保守，避免不必要打扰。
- 图输出必须区分内部决策信息和用户可见消息。

## 7. 技术考虑

- LangGraph 应作为核心依赖引入，并通过项目自有 graph builder 模块隔离。
- 建议模块结构：
  - `adapters/`：nonebot 事件标准化和 QQ 输出执行。
  - `graphs/`：图构建器和图入口。
  - `state/`：类型化图状态和输出模型。
  - `nodes/`：可复用 LangGraph 节点。
  - `tools/`：工具注册表、工具 schema 和工具执行器。
  - `memory/`：记忆提供器接口和适配器。
  - `prompts/`：回复和决策节点的 prompt 构建。
- 现有模块可以在迁移期被包装，但新的图接口必须清晰、显式、可测试。
- 测试应优先使用假的记忆提供器、假的 LLM client 和假的工具，以保证图行为可确定。
- 最终架构应让新增工具只需要注册工具并添加测试，而不是修改主 QQ 消息 handler。

## 8. 分阶段计划

### MVP：LangGraph 基础架构

MVP 的目标是建立新骨架，不要求一次迁移所有旧功能。

包含：
- 类型化图状态。
- MVP 消息图。
- nonebot 到 graph 的适配器。
- 回复决策节点。
- 基础回复生成节点。
- 图执行诊断信息。
- 不依赖真实 QQ / nonebot 的图测试。

MVP 不包含：
- 完整主动行为。
- 所有旧工具完整迁移。
- 完美长期记忆行为。
- 删除所有旧模块。

### Phase 2：记忆与工具迁移

包含：
- 结构化记忆检索节点。
- 工具注册表和工具路由节点。
- 工具执行节点。
- 迁移提醒、日历、搜索和其他现有工具。
- 为迁移能力补充回归测试。

### Phase 3：主动智能与旧路径退役

包含：
- 主动行为图入口。
- 保守的主动决策策略。
- 关系状态 / 话题延续逻辑。
- 更完整的图决策诊断。
- 删除或隔离旧线性编排路径。

## 9. 成功指标

- 新开发者可以通过阅读 graph builder 和状态模型理解主消息流程，而不是在多个 handler 中追踪逻辑。
- 新增工具可以通过工具注册表和测试完成，不需要修改主 QQ 消息 handler。
- 核心消息图测试可以在不启动 nonebot 的情况下运行。
- MVP 集成后，基础直接聊天仍然可用。
- Bot 可以明确判断不回复、普通回复、澄清追问或工具路由。
- 现有关键工具能力可以逐个迁移，不阻塞整体架构改造。
